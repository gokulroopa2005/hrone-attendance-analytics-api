# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Global / Startup | No indexes created on database startup. | Concurrent requests produce duplicate records; queries on 100k records perform collection scans (`COLLSCAN`). | Implemented FastAPI `lifespan` handler calling `init_indexes()` to create unique and query indexes idempotently. |
| 2 | `health` (lines 72-74) | Returns `{"status": "ok"}` unconditionally without checking MongoDB connectivity. | `GET /health` returned HTTP 200 even when MongoDB was stopped or unreachable. | Pinged MongoDB with `client.admin.command("ping")`; on failure, raise HTTP 503 (`Database unavailable`). |
| 3 | `compute_late_minutes` (lines 33-37) | Checked `minutes > 10` after integer division `int(seconds / 60)`. Also ignored IST shift start context. | For punch-in at 09:40:01 on a 09:30 shift, elapsed seconds is 601, `int(601/60) = 10`, `10 > 10` is False, returning 0 instead of 10 (violating R2). | Checked `elapsed_seconds > 600` strictly before integer floor dividing by 60; aligned with IST shift start. |
| 4 | `compute_work_hours` (lines 40-41) | Used Python's built-in `round()`, which performs round-half-to-even (banker's rounding). | 12,690 seconds (3.525 hours) rounded to 3.52 instead of 3.53, violating rule R4 (half-up rounding). | Used `Decimal` with `ROUND_HALF_UP` to round work hours to 2 decimal places. |
| 5 | `compute_overtime` (lines 44-47) | Did not enforce the 30-minute threshold requirement (`max(0, ...)` returned sub-30 minute overtimes). | Working 20 minutes past shift end returned 20 minutes instead of 0, violating rule R3. | Returned 0 if elapsed minutes < 30; otherwise returned elapsed minutes. |
| 6 | `compute_overtime` (lines 44-47) | Subtracted naive datetime from aware IST datetime causing `TypeError`; failed to advance shift end for overnight shifts. | Crashed with `TypeError: can't subtract offset-naive and offset-aware datetimes`, or computed negative overtime for overnight shifts. | Standardized to aware IST datetimes and added 1 calendar day to `shift_end` when `shift_end <= shift_start`. |
| 7 | `punch_in` (lines 102-103) | Used local machine date (`ts.date().isoformat()`) without considering IST or overnight shifts. | An overnight shift punch-in at 05:45 IST on July 7 was saved under July 7 instead of July 6 (the start day, per R1). | Added `compute_attendance_date()` converting to IST and attributing pre-shift-end overnight punches to the previous day. |
| 8 | `create_employee` (lines 79-83) | Check-then-insert race condition (`find_one` followed by `insert_one`). | Concurrent requests with the same `emp_code` both passed `find_one` and created duplicate records. | Created unique index on `emp_code` and caught `pymongo.errors.DuplicateKeyError` to return HTTP 409. |
| 9 | `create_employee` / `EmployeeIn` (lines 53-61, 78-85) | Did not validate `shift_start != shift_end`, lacked regex patterns, and returned `created_at` as ISO string. | Submitting identical shifts returned 201 instead of 422; response did not match `EpochMillis` schema. | Added Pydantic validators (`shift_start != shift_end`, regexes) and formatted `created_at` as epoch milliseconds. |
| 10 | `list_employees` (line 93) | Off-by-one pagination skip calculation: `skip = page * page_size`. | Requesting `page=1` skipped the first 20 records (`skip=20`), omitting page 1 entirely. | Changed calculation to `skip = (page - 1) * page_size`. |
| 11 | `list_employees` (lines 89-95) | `total` counted the entire collection ignoring `department` filter, and results were not sorted. | Total count failed to reflect filter; employees were returned in arbitrary MongoDB natural order. | Used `count_documents(q)`, added `.sort("emp_code", ASCENDING)`, and formatted response fields to match schema. |
| 12 | `punch_in` (lines 101, 113) | Missing employee caused `emp` to be `None`, raising unhandled `TypeError` on `emp["shift_start"]`. | `POST /attendance/punch-in` for an unknown employee returned HTTP 500 instead of HTTP 404. | Added explicit `if not emp: raise HTTPException(404, "Employee not found")`. |
| 13 | `punch_in` (lines 104-105) | Check-then-insert race condition, and accepted any arbitrary status string. | Concurrent punch-ins inserted duplicates; invalid statuses like `ABSENT` were accepted with 201. | Enforced unique compound index on `(emp_code, date)` catching `DuplicateKeyError` (409), and restricted status to `PRESENT`, `WFH`, `ON_DUTY`. |
| 14 | `list_attendance` (lines 144-147) | Memory exhaustion: loaded entire collection into Python RAM (`list(find())`) before sorting and slicing. | Querying 100,000 records crashed process memory or timed out. | Pushed pagination (`skip`/`limit`) and composite sorting (`[("date", -1), ("emp_code", 1)]`) down to MongoDB cursor. |
| 15 | `list_attendance` (lines 125-146) | Did not validate `date_from <= date_to`, and missed secondary sort on `emp_code`. | Passing `date_from > date_to` returned 200 instead of 422; records on same date were unordered. | Validated date formats and range returning 422 on invalid ranges; sorted by `date` DESC and `emp_code` ASC. |
| 16 | `punch_in` & `list_attendance` (lines 119, 149) | Injected non-spec `"id"` field (`str(inserted_id)`) and returned raw datetimes instead of epoch milliseconds. | Responses failed schema validation against `AttendanceRecord` in `openapi.yaml`. | Removed `"id"` field and converted all instants (`punch_in`, `punch_out`, history) to integer epoch milliseconds. |
| 17 | `list_attendance` (lines 129, 137) | Query parameter `status` shadowed FastAPI's `status` module when accessing `status.HTTP_422_UNPROCESSABLE_ENTITY`. | Input validation failure on `date_from > date_to` crashed with `AttributeError` and returned HTTP 500 instead of HTTP 422. | Used explicit HTTP integer status codes (422, 404, 409, 503) and renamed module import to `http_status`. |

### Examined and Decided NOT a Defect

1. **Module-level `MongoClient` instance**: Initializing `client = MongoClient(...)` at module level is standard for PyMongo and FastAPI. PyMongo manages an internal connection pool across worker threads, avoiding reconnection overhead per request.
2. **MongoDB generating internal `_id`**: Storing documents with MongoDB's `_id` ObjectId is required internally by MongoDB; keeping `_id` in the database while projecting or stripping it from API responses complies with the requirement that `_id` is never exposed.
